# Domain Docs

This repository uses a single-context domain layout:

- `GLOSSARY.md` at the repository root.
- Architecture decision records in `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the area being explored.
If these files do not exist, proceed silently. Domain-modeling work
creates them when terminology or decisions are resolved.

## Vocabulary

Use the glossary's terms in issues, proposals, hypotheses, and tests.
If a needed concept is missing, reconsider the wording or note the gap
for domain-modeling work.

## Decisions

If a proposal contradicts an existing ADR, identify the ADR and explain
why the decision should be reconsidered.
